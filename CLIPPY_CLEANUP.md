# Rust Clippy cleanup backlog

This is a checklist of suppressions in the Turborepo Rust workspace. Work in focused changes; do not remove an allowance without checking what it hides. Use `cargo lint` for the full workspace and focused `cargo clippy -p <package> --all-targets -- -D warnings` while iterating. Keep behavior and public APIs stable unless a change is deliberate and tested.

- [x] **Replace the broad `globwatch` suppression.** Removed `clippy::all` from `crates/turborepo-globwatch/src/lib.rs` and fixed the byte-slice warnings. A function-scoped `#[expect(clippy::manual_try_fold)]` preserves the deliberate behavior of attempting every watch path and collecting all errors rather than stopping at the first one. Focused Clippy and tests pass.
- [x] **Enable `too_many_arguments` for new code.** Removed the workspace-wide allowance from `Cargo.toml`. Eight additional functions triggered the lint: combined cached dependency/ancestor sets in `turborepo-boundaries` to eliminate one violation; documented seven remaining exceptions on individual functions with `#[expect]` rather than changing task-hash APIs or uv task-generation calls merely to satisfy the lint. Workspace Clippy passes.
- [x] **Review existing local `too_many_arguments` allowances.** Of the 21 pre-existing annotations, seven were stale and are removed. Fourteen still cover real lint findings and now use `#[expect]`, so future changes that make them unnecessary will fail strict Clippy. Refactor signatures only when grouping arguments genuinely clarifies an API; the seven new exceptions from the workspace-wide cleanup remain function-scoped.
- [x] **Narrow production `unwrap_used` / `expect_used` exemptions.** Removed both crate-wide allowances from `crates/turborepo-repository/src/lib.rs`. Of the 24 newly exposed calls, three were removed without changing normal behavior; the other 21 now have function-scoped `#[expect]` annotations documenting their invariants. Test-only allowances and the workspace's default denials remain in place.
- [ ] **Replace repository panic invariants where behavior should change.** The remaining 21 calls cover static validated literals, graph/index invariants, and paths assumed to have parents. Add characterization tests before converting a reachable panic to a recoverable error; don't silently change failure behavior just to appease Clippy.
- [ ] **Audit broad `result_large_err` allowances incrementally.** Determine which methods actually trigger the lint; move justified exceptions close to them. Don't box errors reflexively: consider allocations, error APIs, and hot paths.
  - [x] Remove crate-wide allowances from `turborepo-scm`, `turborepo-microfrontends-config`, `turborepo-run-opts`, `turborepo-watch`, and `turborepo-query-api`. One allowance was stale; ten function-scoped expectations preserve existing structured error APIs.
  - [ ] Review the remaining crate-wide and module-wide allowances, especially `turborepo-cli`, `turborepo-config`, and `turborepo-repository`.
- [x] **Review other crate-wide exceptions individually.** Removed `needless_lifetimes` from config and daemon, `uninlined_format_args` from daemon, and `sliced_string_as_bytes` from boundaries. Elided the one unnecessary config lifetime and rewrote two boundaries byte slices; daemon needed no replacement exceptions.

Keep intentional or separately scoped exceptions separate from this cleanup: the guarded Biome deserialization call in `crates/turborepo-errors/src/json.rs`, the FSEvents bitflags allowance in `crates/turborepo-filewatch/src/fsevent.rs`, and test panic-extraction allowances. `turborepo-wax` is a fork of upstream code and needs a separate maintenance decision before changing its blanket allowance. Do not touch Ghostty for this effort.
