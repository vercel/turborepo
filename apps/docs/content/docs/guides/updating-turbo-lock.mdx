[`turbo.lock`](/docs/core-concepts/managed-toolchains#turbolock) records the exact toolchain that your declarations resolve to. When a dependency bot changes one of those declarations, the same pull request must update `turbo.lock`. Otherwise, [frozen mode](/docs/reference/setup#frozen-mode) stops `turbo setup` in CI:

```txt title="Terminal"
turbo.lock declarations changed: pnpm: package.json (/packageManager)
```

## Updates that change `turbo.lock`

Only changes to the [declarations](/docs/reference/setup#supported-declarations) that `turbo.lock` records require a lock update:

| Declaration                                   | Renovate manager |
| --------------------------------------------- | ---------------- |
| `.nvmrc`                                      | `nvm`            |
| `.node-version`                               | `nodenv`         |
| `engines.node` in `package.json`              | `npm`            |
| `devEngines.runtime` in `package.json`        | `npm`            |
| `packageManager` in `package.json`            | `npm`            |
| `devEngines.packageManager` in `package.json` | `npm`            |
| `rust-toolchain.toml` or `rust-toolchain`     | `rust-toolchain` |
| `.python-version`                             | `pyenv`          |
| The `go` and `toolchain` directives in `go.mod` | `gomod`        |

Updates to your dependencies and your package managers' lockfiles don't affect `turbo.lock`, so frozen `turbo setup` still passes on those pull requests.

[Additional tools](/docs/reference/additional-tools) are declared in `turbo.json` with exact URLs and digests, so bots don't update them. Review those changes like code.

## Renovate

Renovate can run `turbo setup` after it updates a declaration, using [`postUpgradeTasks`](https://docs.renovatebot.com/configuration-options/#postupgradetasks). Renovate only runs commands that match its [`allowedCommands`](https://docs.renovatebot.com/self-hosted-configuration/#allowedcommands) setting, and `turbo` must be installed where Renovate runs, so this requires self-hosted Renovate. With the Mend-hosted Renovate app, [update `turbo.lock` on the branch](#dependabot-and-other-tools) instead.

<Steps>
<Step>
### Install `turbo` where Renovate runs

Install the [standalone `turbo` binary](/docs/getting-started/installation#global-installation) in the environment that runs Renovate, so that `turbo` is on its `PATH`. The global binary runs `turbo setup` itself, so Renovate doesn't need to install your dependencies first.

The environment must also meet the [requirements for `turbo setup`](/docs/reference/setup#requirements), including having [no npm configuration](/docs/reference/setup#npm-configuration-is-rejected) that could redirect downloads.

</Step>
<Step>
### Allow the command

Add the command to `allowedCommands` in your self-hosted Renovate configuration:

```js title="config.js"
module.exports = {
  allowedCommands: ["^turbo setup --tools-only --no-frozen$"],
};
```

</Step>
<Step>
### Run `turbo setup` after toolchain updates

Add package rules to your repository's Renovate configuration:

```json title="./renovate.json"
{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "packageRules": [
    {
      "matchManagers": ["npm", "nvm", "nodenv"],
      "matchDepNames": ["node", "pnpm"],
      "postUpgradeTasks": {
        "commands": ["turbo setup --tools-only --no-frozen"],
        "fileFilters": ["turbo.lock"]
      }
    }
  ]
}
```

Replace `pnpm` with your package manager. If you use Rust, Python, or Go, add rules for their managers too:

```json title="./renovate.json"
{
  "$schema": "https://docs.renovatebot.com/renovate-schema.json",
  "packageRules": [
    {
      "matchManagers": ["rust-toolchain", "pyenv"],
      "postUpgradeTasks": {
        "commands": ["turbo setup --tools-only --no-frozen"],
        "fileFilters": ["turbo.lock"]
      }
    },
    {
      "matchManagers": ["gomod"],
      "matchDepTypes": ["golang", "toolchain"],
      "postUpgradeTasks": {
        "commands": ["turbo setup --tools-only --no-frozen"],
        "fileFilters": ["turbo.lock"]
      }
    }
  ]
}
```

</Step>
</Steps>

When Renovate updates a declaration, it runs `turbo setup` in its checkout. `turbo setup` re-resolves only the changed tool and installs the toolchain, and Renovate commits the updated `turbo.lock` with the declaration change:

```txt title="Terminal"
javascript: tools managed (inferred); dependencies skipped (--tools-only)
turbo.lock updated. Commit turbo.lock to share the exact managed tool selections.
pnpm: 10.18.0 -> 10.18.1
node 24.21.0: reused
pnpm 10.18.1: installed
...
```

When a branch groups several updates, later runs find `turbo.lock` already current and leave it unchanged.

This configuration relies on these settings:

- **`--no-frozen`**: Renovate sets `CI=true` for every command it runs, so `turbo setup` would otherwise use frozen mode and fail on the changed declaration. `--no-frozen` uses local mode, which updates `turbo.lock`.
- **`--tools-only`**: Updating `turbo.lock` doesn't need your dependencies, so Renovate's run skips installing them.
- **`fileFilters`**: Limits the files that Renovate commits to `turbo.lock`. The installed tools in `.turbo/tools` are Git-ignored, so they're never committed.
- **`matchManagers`, `matchDepNames`, and `matchDepTypes`**: Limit the task to toolchain updates. Other updates don't change `turbo.lock`, so running `turbo setup` for them only adds time.

## Dependabot and other tools

Dependabot can't run commands, so it can't update `turbo.lock`. The same applies to any tool or edit that changes a declaration without running `turbo setup`, such as editing `.nvmrc` in your Git provider's web interface.

When one of these pull requests changes a declaration, update `turbo.lock` on its branch from a machine that can run `turbo setup`:

```bash title="Terminal"
gh pr checkout <number>
turbo setup --tools-only
git add turbo.lock
git commit -m "chore: Update turbo.lock"
git push
```

Outside of CI, `turbo setup` uses local mode, so it updates `turbo.lock` and prints each change:

```txt title="Terminal"
javascript: tools managed (inferred); dependencies skipped (--tools-only)
turbo.lock updated. Commit turbo.lock to share the exact managed tool selections.
pnpm: 10.18.0 -> 10.18.1
...
```
