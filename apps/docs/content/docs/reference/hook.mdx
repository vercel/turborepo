Print a shell hook that puts your repository's [managed toolchains](/docs/core-concepts/managed-toolchains) first on `PATH` while your shell is inside the repository. Commands you type, such as `node` or `pnpm install`, then use the versions in `turbo.lock`.

```bash title="Terminal"
turbo hook <shell>
```

`<shell>` is `bash`, `zsh`, `fish`, or `powershell` (also accepted as `pwsh`).

<Callout type="warn">
  The shell hook is experimental. It only activates tools in repositories that
  enable
  [`futureFlags.experimentalSetup`](/docs/reference/configuration#experimentalsetup)
  and only on the platforms that managed toolchains support (macOS and Linux
  with glibc). Everywhere else, it doesn't activate anything.
</Callout>

## Installing the hook

The [standalone installer](/docs/getting-started/installation#global-installation) for macOS and Linux adds the hook for you. To add it yourself, put the line for your shell at the end of its startup file:

| Shell      | File                         | Line                                                  |
| ---------- | ---------------------------- | ----------------------------------------------------- |
| zsh        | `~/.zshrc`                   | `eval "$(turbo hook zsh)"`                            |
| bash       | `~/.bashrc`                  | `eval "$(turbo hook bash)"`                           |
| fish       | `~/.config/fish/config.fish` | `turbo hook fish \| source`                           |
| PowerShell | `$PROFILE`                   | `Invoke-Expression (& turbo hook powershell \| Out-String)` |

Open a new shell for the change to take effect. The hook records the path of the `turbo` binary that printed it, so later prompts don't depend on which `turbo` comes first on `PATH`.

`cmd.exe` has no prompt hook. Use [`turbo exec`](#when-to-use-turbo-exec) instead.

### The installer and opting out

On macOS and Linux, `curl -fsSL https://turborepo.dev/install | sh` adds the hook to `~/.zshrc` for zsh, and to `~/.bashrc` (plus `~/.bash_profile` or `~/.bash_login`, if one exists) for bash. For fish, it prints the line to add yourself. It adds the hook only when the installed version of `turbo` supports it, and never in GitHub Actions.

The installer marks its line with `# Turborepo standalone installer shell hook`. Running the installer again, or upgrading, updates that line instead of adding another. To skip the hook, use any of these:

```bash title="Terminal"
curl -fsSL https://turborepo.dev/install | sh -s -- --no-shell-hook
curl -fsSL https://turborepo.dev/install | TURBO_NO_SHELL_HOOK=1 sh
# Skips both PATH and the hook: the installer edits no shell profiles.
curl -fsSL https://turborepo.dev/install | sh -s -- --no-modify-path
curl -fsSL https://turborepo.dev/install | TURBO_NO_MODIFY_PATH=1 sh
```

The Windows installer doesn't add the hook yet.

## What the hook changes

Before each prompt, and after each directory change in zsh and fish, the hook runs `turbo` to check your current directory:

1. It looks for the nearest `turbo.lock` in the current directory or its parents, stopping at the root of the Git repository. A repository nested inside another, such as a clone in a `vendor/` directory, never uses its parent's tools.
2. If the repository's root `turbo.json` or `turbo.jsonc` doesn't enable `futureFlags.experimentalSetup`, the hook does nothing.
3. If `turbo setup` installed tools for this clone, the hook puts their directory first on `PATH`.

When you leave the repository, the hook removes that one entry and leaves the rest of `PATH`, including changes you made in the meantime, exactly as it was. Switching directly to another managed repository swaps one repository's tools for the other's.

The hook only changes `PATH` and an internal `__TURBO_HOOK_STATE` variable that remembers what it added. It never downloads or installs tools, never writes `turbo.lock`, and never hands off to a [repository-local `turbo`](/docs/core-concepts/managed-toolchains#repository-local-turbo).

### Trust

The hook activates only binaries that `turbo setup` installed and recorded for your user. `turbo setup` records each clone it sets up in `turbo`'s user state directory, outside the repository. A `.turbo/tools` directory alone, such as one checked into a repository you just cloned, is never activated. The installation must match the record for that exact clone, so moving or recloning a repository requires `turbo setup` again.

### Out-of-date and missing tools

When `turbo.lock` changes after `turbo setup` ran, for example after `git pull`, the hook keeps the previously installed tools active and prints:

```txt title="Terminal"
turbo: turbo.lock changed since `turbo setup`; keeping the previously installed tools active. Run `turbo setup` to update them.
```

If the tools are missing or were never installed for this clone, the hook activates nothing and asks you to run `turbo setup`. Notices appear when you enter a repository and when its state changes, not at every prompt.

The hook is deliberately lenient so your shell keeps working. [`turbo run`](/docs/core-concepts/managed-toolchains#how-turbo-run-uses-managed-tools) and `turbo exec` stay strict: they fail until you run `turbo setup`.

### Prompt latency

The hook starts one `turbo` process per prompt. When nothing relevant changed since the last prompt, it only checks a few file timestamps, so the cost is about the same as `turbo --version`. Outside repositories with a `turbo.lock`, it only searches for one.

If your global `turbo` comes from npm instead of the standalone binary, the npm wrapper starts Node.js each time a new shell prints the hook. Later prompts run the native binary directly.

## Removing the hook

Delete the hook line from your shell's startup file. If the installer added it, it's the line that ends with `# Turborepo standalone installer shell hook`. Then open a new shell. Shells that are already open keep the hook until they exit.

## When to use `turbo exec`

The hook only affects interactive shells that load it. To run a single command with the managed tools anywhere else, use `turbo exec`:

```bash title="Terminal"
turbo exec -- pnpm install
```

Use `turbo exec` for:

- **Scripts and CI steps.** Non-interactive shells don't draw prompts, so the hook never runs.
- **`cmd.exe`.** It has no prompt hook.
- **GUI-launched processes.** Editors and other applications that start tools directly don't load your shell's startup files.
- **Machines without the hook.** For example, when you installed `turbo` with `--no-shell-hook`.

`turbo exec` uses the same tools as `turbo run`, and it fails instead of running out-of-date tools.
