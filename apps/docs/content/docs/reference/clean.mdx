Delete the files that tasks write as their [`outputs`](/docs/reference/configuration#outputs).

```bash title="Terminal"
turbo clean [tasks] [options]
```

Turborepo already knows every task's outputs, so you don't have to repeat them in `rm -rf` scripts. `turbo clean` selects tasks the same way [`turbo run`](/docs/reference/run) does, including `dependsOn` and [Package Configurations](/docs/reference/package-configurations). It resolves each task's outputs exactly as the cache does when it saves them, including `!` exclusions and outputs under symlinked output directories. It then deletes those files, except for the paths it can't prove are build outputs (see [Safety](#safety)).

```bash title="Terminal"
# Delete the outputs of every package's `build` task
turbo clean build

# Delete the outputs of web#build and of the tasks it depends on
turbo clean build --filter=web

# Preview what would be deleted
turbo clean build --dry
```

## Enabling `turbo clean`

`turbo clean` is experimental. Enable it with the `experimentalClean` [future flag](/docs/reference/configuration#futureflags) in your root `turbo.json`:

```jsonc title="./turbo.json"
{
  "futureFlags": {
    "experimentalClean": true,
  },
}
```

<Callout type="info" title="Running a task named clean">
  Without the flag, `turbo clean` runs a task named `clean`, as it always has.
  This includes forms like `turbo clean --filter=web` and `turbo clean build`.
  With the flag, `turbo clean` runs this command instead. To run a task named
  `clean`, use `turbo run clean`.
</Callout>

## What gets deleted

For each selected task, `turbo clean` deletes the files and symlinks that match its `outputs`. A directory is deleted only when everything inside it has been deleted. For example, with `"outputs": ["dist/**", "!dist/keep.txt"]`, the files in `dist` are deleted but `dist/keep.txt` and the `dist` directory are kept.

These tasks are skipped and reported:

- Tasks without `outputs`.
- Tasks with [`"cache": false`](/docs/reference/configuration#cache).
- [Persistent](/docs/reference/configuration#persistent) tasks.

Task logs in `.turbo` are not deleted; the next cache hit rewrites them.

Arguments after `--` are passed to task planning the same way as for `turbo run`, so outputs that depend on them resolve the same way.

When some files can't be deleted, for example because of permissions, `turbo clean` keeps going. It reports each failure and how many files were actually deleted, and exits with a non-zero code.

### Allowed output patterns

`turbo clean` only expands output patterns that are anchored inside their package:

- A literal first segment, like `"dist/**"`, `".next/**"` or `"tsconfig.tsbuildinfo"`.
- A brace set of literal directories, like `"{dist,build}/**"`.
- A file extension at the package root, like `"*.tsbuildinfo"`.

Other patterns are skipped and reported, and nothing they match is deleted. This includes patterns with a `..` segment, patterns that start with a wildcard (`"**/*.js"`, `"*.*"`, `"?*"`), and patterns whose wildcards would apply to a package directory (`"packages/**"` in a root task). Outputs outside the package, such as those reached with `..` or `$TURBO_ROOT$`, are not cleaned. To clean such outputs, anchor them in a directory, like `"dist/**"`.

### Safety

`turbo clean` deletes files on your machine. When it can't prove that a path is a build output, it keeps the path and reports it:

- `turbo clean` needs a git repository with a readable index. Git-tracked files are never deleted, and that includes tracked symlinks. If it can't read the set of tracked files, `turbo clean` deletes nothing. It reads the index directly, so it doesn't need a `git` binary.
- Paths are compared using the names stored on disk. On case-insensitive or Unicode-normalizing filesystems, an output spelled `Index.ts` can't delete a tracked `index.ts`.
- Nothing inside a git submodule or a nested repository is deleted.
- Nothing outside the repository is deleted. Nothing reached through a symlink is deleted either: a symlink that matches `outputs` is deleted itself, but its target is never touched. On Linux and macOS, if a directory is replaced by a symlink while `turbo clean` runs, the deletion fails instead of following the link.
- The repository root, package directories, and any directory that contains a package are never deleted.
- Nothing inside `node_modules`, `.git`, or `.turbo` is deleted.

Planning never touches the cache. `turbo clean` doesn't read, write, or evict cache entries, even with [`cacheMaxAge`](/docs/reference/configuration#cachemaxage) set.

## Options

#### `--dry` / `--dry-run`

List what would be deleted without deleting anything. Directories that would be deleted are listed once, with a trailing `/`.

#### `--filter <string>`

Aliased as `-F`.

Select the packages whose tasks are cleaned. The syntax is the same as [`turbo run --filter`](/docs/reference/run#--filter-string).

#### `--affected`

Select packages that are affected by changes between the current branch and `main`, the same as [`turbo run --affected`](/docs/reference/run#--affected).

#### `--only`

Clean only the tasks specified, not the tasks they depend on. The same as [`turbo run --only`](/docs/reference/run#--only).
