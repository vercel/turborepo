`setup.additionalTools` in the root `turbo.json` declares command-line tools that `turbo setup` has no built-in support for, such as an internal company CLI. For each tool, you pin an exact version and, for each platform, the URL and SHA-256 digest of a downloadable binary or archive. `turbo setup` records the declaration in `turbo.lock`, downloads and verifies the artifact, and installs it into `.turbo/tools` next to the managed Node.js. It never runs scripts from the tool or the repository.

<Callout type="warn">
  Additional tools are experimental and require `futureFlags.experimentalSetup`.
  In this release, `turbo setup` installs them, but they aren't available to
  tasks yet: `turbo run` doesn't put them on `PATH`. Activation in `turbo run`
  and `turbo exec`, and including them in task hashes, will arrive in later
  releases. Read the [limitations](#limitations) before trying them.
</Callout>

## Declaring a tool

<Steps>
<Step>
### Collect the artifacts

For each platform you support, find the release artifact and compute its SHA-256 digest from a copy you trust:

```bash title="Terminal"
shasum -a 256 acme-1.4.2-linux-x64.tar.gz
```

On Linux, `sha256sum` prints the same digest. Look inside each archive: every entry must be under a single top-level directory, such as `acme-1.4.2/`.

```txt title="acme-1.4.2-linux-x64.tar.gz"
acme-1.4.2/
├── bin/
│   └── acme          # the executable
└── share/
    └── templates/    # resources the executable reads at runtime
```

</Step>
<Step>
### Declare the tool

Add the tool under `setup.additionalTools` in the root `turbo.json`:

```jsonc title="./turbo.json"
{
  "$schema": "https://turborepo.dev/schema.json",
  "futureFlags": {
    "experimentalSetup": true,
  },
  "setup": {
    "additionalTools": {
      "acme": {
        "version": "1.4.2",
        "artifacts": {
          "macos-arm64": {
            "url": "https://downloads.example.com/acme/1.4.2/acme-1.4.2-macos-arm64.tar.gz",
            "sha256": "4b5e2f0d9c8a7b6e5d4c3b2a1f0e9d8c7b6a5f4e3d2c1b0a9f8e7d6c5b4a3f2e",
            "format": "tar-gz",
            "rootPrefix": "acme-1.4.2",
            "executables": { "acme": "bin/acme" },
          },
          "linux-x64-gnu": {
            "url": "https://downloads.example.com/acme/1.4.2/acme-1.4.2-linux-x64.tar.gz",
            "sha256": "9c1d0e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d",
            "format": "tar-gz",
            "rootPrefix": "acme-1.4.2",
            "executables": { "acme": "bin/acme" },
          },
        },
      },
    },
  },
}
```

`turbo setup` keeps the whole tree under `rootPrefix`, so `bin/acme` can still find `share/templates` next to it.

</Step>
<Step>
### Run `turbo setup`

```bash title="Terminal"
turbo setup --tools-only
```

```txt title="Terminal"
turbo.lock created. Commit turbo.lock to share the exact managed tool selections.
acme: locked 1.4.2
node: locked 24.21.0
node 24.21.0: installed
acme 1.4.2: installed (https://downloads.example.com/acme/1.4.2/acme-1.4.2-linux-x64.tar.gz)
Dependencies skipped (--tools-only). No tasks run; managed activation is not enabled.
```

Each additional tool's line names the URL it came from.

</Step>
<Step>
### Commit `turbo.json` and `turbo.lock`

Every contributor and CI job then installs the same bytes. Review later changes to `setup.additionalTools` like code changes. See [Trust boundary](#trust-boundary).

</Step>
</Steps>

A single executable file uses `"format": "binary"`, no `rootPrefix`, and exactly one executable, whose path is where `turbo setup` installs it:

```jsonc title="./turbo.json"
"linux-x64-gnu": {
  "url": "https://downloads.example.com/acme/1.4.2/acme-linux-x64",
  "sha256": "9c1d0e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d",
  "format": "binary",
  "executables": { "acme": "bin/acme" },
}
```

## Fields

| Field                     | Required      | Description                                                                                                                                             |
| ------------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `additionalTools.<id>`    | Yes           | The tool ID. It starts with a lowercase letter and has at most 64 lowercase letters, digits, `-`, or `_`.                                               |
| `version`                 | Yes           | An exact version, such as `1.4.2`. Ranges like `1.x` and channels like `latest`, `stable`, `lts`, `nightly`, or `current` are rejected.                 |
| `artifacts`               | Yes           | Artifacts keyed by [platform](#platforms). Declare at least one.                                                                                        |
| `artifacts.*.url`         | Yes           | An HTTPS URL without credentials, a query, or a fragment.                                                                                               |
| `artifacts.*.sha256`      | Yes           | The lowercase hex SHA-256 digest of the downloaded bytes.                                                                                               |
| `artifacts.*.format`      | Yes           | `binary`, `tar`, `tar-gz`, or `zip`.                                                                                                                    |
| `artifacts.*.rootPrefix`  | Archives only | The single top-level directory that contains every archive entry, as one directory name. Not allowed for `binary`.                                      |
| `artifacts.*.executables` | Yes           | Executable names mapped to paths relative to `rootPrefix`, or, for `binary`, to the install path. Up to 64 for an archive and exactly one for `binary`. |

Paths are relative and portable: ASCII letters, digits, `.`, `_`, `-`, `+`, and `@`, separated by `/`, with no `..` segments or Windows device names such as `CON`. Unknown fields are errors, so there's nowhere to declare install scripts or commands.

### Platforms

| Platform           | Installs in this release |
| ------------------ | ------------------------ |
| `macos-x64`        | Yes                      |
| `macos-arm64`      | Yes                      |
| `linux-x64-gnu`    | Yes                      |
| `linux-arm64-gnu`  | Yes                      |
| `linux-x64-musl`   | No                       |
| `linux-arm64-musl` | No                       |
| `windows-x64`      | No                       |
| `windows-arm64`    | No                       |

`turbo.lock` records every platform you declare, so you can declare musl and Windows artifacts today, but `turbo setup` doesn't install tools on those hosts yet. On a supported host without an artifact for its platform, `turbo setup` fails instead of substituting another platform's artifact.

## How `turbo setup` handles additional tools

### `turbo.lock`

A declaration is already exact, so `turbo setup` copies it into `turbo.lock` without resolving anything:

```jsonc title="./turbo.lock"
{
  "schemaVersion": 0,
  "tools": {
    "acme": {
      "adapter": "artifact",
      "version": "1.4.2",
      "declarations": [
        {
          "file": "turbo.json",
          "field": "/setup/additionalTools/acme",
          "request": "1.4.2",
        },
      ],
      "installation": {
        "kind": "managed",
        "artifacts": {
          "linux-x64-gnu": {
            "artifact": {
              "url": "https://downloads.example.com/acme/1.4.2/acme-1.4.2-linux-x64.tar.gz",
              "sha256": "9c1d0e2f3a4b5c6d7e8f9a0b1c2d3e4f5a6b7c8d9e0f1a2b3c4d5e6f7a8b9c0d",
              "format": "tar-gz",
              "rootPrefix": "acme-1.4.2",
              "executables": { "acme": "bin/acme" },
            },
          },
          // ...macos-arm64
        },
      },
    },
    "node": {
      // ...
    },
  },
}
```

Any edit to a declaration, including a new digest, URL, layout, or platform under the same version, counts as a changed declaration.

| Situation                 | Local `turbo setup`                                          | Frozen or CI `turbo setup` |
| ------------------------- | ------------------------------------------------------------ | -------------------------- |
| No `turbo.lock`           | Creates it                                                   | Fails                      |
| Nothing changed           | Reuses the installation without downloading                  | Same                       |
| A declaration changed     | Rewrites only that tool's entry, prints the change, installs | Fails and names the tool   |
| A declaration was removed | Removes the entry and the installed tool                     | Fails and names the tool   |
| `--update-lock`           | Leaves additional tools unchanged                            | Requires `--no-frozen`     |
| `--force`                 | Downloads, verifies, and reinstalls the locked artifacts     | Same                       |

```txt title="Terminal"
turbo.lock updated. Commit turbo.lock to share the exact managed tool selections.
acme: 1.4.2 (selection changed)
```

### Downloads and installation

- **Exact origins.** `turbo setup` only connects to the origins of the locked URLs and rejects redirects.
- **Verified first.** The download must match `sha256` before anything is unpacked or installed.
- **Bounded.** Each artifact is limited to 256 MiB downloaded, 512 MiB extracted, and five minutes.
- **Safe extraction.** Archive entries must stay inside `rootPrefix`. Each executable must be a regular file inside `rootPrefix` with its executable permission set in the archive. Zip archives created on Windows don't record permissions, so they can't provide executables for macOS or Linux.
- **Atomic.** Tools install into a new generation in `.turbo/tools`. If anything fails, the previous installation stays in place.
- **Proxies and certificates.** Downloads honor `HTTPS_PROXY`, `HTTP_PROXY`, `NO_PROXY`, `SSL_CERT_FILE`, and `SSL_CERT_DIR`.

In local mode, `turbo setup` updates `turbo.lock` before it downloads. If the new artifact then fails to download or verify, fix the declaration and run `turbo setup` again.

## Trust boundary

A SHA-256 digest pins the exact bytes that `turbo setup` installs. It doesn't make the publisher trustworthy, and it doesn't check what the bytes do. When you declare a tool, your repository vouches for it:

- Anyone who can change `setup.additionalTools` can make every contributor and CI job download and later run different bytes. Review those changes like code, for example with a `CODEOWNERS` entry for `turbo.json`.
- Take the digest from a source you trust. A checksum file downloaded from the same server as the artifact only proves that the bytes match what that server published.
- `version` is a label. `turbo setup` records it but doesn't check it against the tool.
- `turbo setup` reports each tool's source URL so reviewers and CI logs show where the bytes came from.
- Credentials never belong in `turbo.json` or `turbo.lock`. URLs with credentials, queries, or fragments are rejected, and authenticated downloads aren't supported yet. Keep proxy settings in your environment.

### What `turbo setup` won't do

Additional tools cover downloadable binaries and archives that run where they're unpacked. `turbo setup` doesn't:

- Run install scripts or commands from the tool or the repository.
- Install system libraries or system packages.
- Run privileged installers, such as `.pkg` or `.msi` packages, or anything that needs `sudo`.
- Start services or daemons.
- Build tools from source.
- Install tools through a package manager or load executable plugins. Package-manager-backed sources may be supported later.
- Change your global `PATH` or run Turborepo tasks.

If a tool is already a dependency of your repository, such as an npm package in `package.json`, keep declaring it there. Its native lockfile already pins it, and the package manager installs it.

## Collisions

`turbo setup` rejects declarations that would shadow a built-in tool or another additional tool:

- **Built-in tools.** These IDs are reserved: `bun`, `go`, `javascript`, `node`, `npm`, `pnpm`, `python`, `rust`, `rustup`, `turbo`, `uv`, and `yarn`. Declare those tools in their native files instead.
- **Built-in executables.** Executables that built-in tools provide are reserved, such as `node`, `npm`, `npx`, `pnpm`, `corepack`, `cargo`, `rustc`, `go`, `python`, `uv`, and `turbo`.
- **Other additional tools.** Each executable name can belong to only one tool on each platform. Names are compared case-insensitively, and on Windows the `.exe`, `.cmd`, `.bat`, and `.com` extensions are ignored.

```txt title="Terminal"
  x Invalid additional tool "lint": executable "acme" is also declared by "acme".
```

## Limitations

This experimental release has these limitations:

- **Not available to tasks yet.** `turbo run` doesn't put additional tools on `PATH`, and `turbo exec` doesn't exist yet. Task hashes don't include them.
- **No `--check`.** `turbo setup --check` fails when `turbo.lock` contains additional tools.
- **Tools-only setup with Node.js.** `--tools-only` is required, and the repository still needs a Node.js declaration, such as `.nvmrc`.
- **No other `setup` keys.** `turbo setup` refuses a `setup` object that contains anything besides `additionalTools`.
- **macOS and Linux with glibc only.** See [Platforms](#platforms).
- **No redirects, mirrors, offline installs, or authenticated downloads.** URLs that redirect, such as GitHub release downloads, fail.
- **Single-directory archives.** Archives must have one top-level directory.

## Troubleshooting

| Message                                                                    | Fix                                                                                                                                       |
| -------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------- |
| `Invalid additional tool "<id>": ...`                                      | Fix the field that the message and its label point at.                                                                                    |
| `"<id>" is managed by a built-in setup adapter`                            | Declare the tool in its native file, such as `.nvmrc` or `package.json`.                                                                  |
| `setup.additionalTools changed for {"<id>"}`                               | Run `turbo setup --tools-only` locally and commit `turbo.lock`.                                                                           |
| `additional tool "<id>" has no artifact for <platform>`                    | Add an artifact for that platform under `setup.additionalTools.<id>.artifacts`.                                                           |
| `cannot download additional tool "<id>": artifact SHA-256 does not match`  | The bytes at the URL changed or the digest is wrong. Verify the artifact and fix `sha256`.                                                |
| `cannot download additional tool "<id>": download redirects are forbidden` | Use a URL that serves the artifact directly.                                                                                              |
| `invalid inventory, tool identity or executable collision`                 | Check that every executable path exists in the archive and has its executable permission set.                                             |
| `activation planning supports only managed Node/pnpm`                      | `--check` doesn't support additional tools yet. `turbo setup --frozen --tools-only` checks `turbo.lock` and reuses healthy installations. |
| `unsupported setup request: a native Node declaration is required`         | Add a Node.js declaration, such as `.nvmrc`, at the repository root.                                                                      |
| `official-only setup rejects ... configuration`                            | Remove `setup` keys other than `additionalTools`.                                                                                         |
