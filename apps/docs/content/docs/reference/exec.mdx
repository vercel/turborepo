Run one command with the repository's [managed toolchains](/docs/core-concepts/managed-toolchains).

```bash title="Terminal"
turbo exec [flags] -- <command> [args...]
```

```bash title="Terminal"
turbo exec -- node --version
turbo exec -- pnpm install --frozen-lockfile
```

`turbo exec` uses the same managed environment that [`turbo run`](/docs/reference/run) gives tasks: the tools that [`turbo setup`](/docs/reference/setup) installed come first on `PATH`, followed by your `PATH`, along with the variables those tools need, such as `CARGO_HOME`, `GOROOT`, or uv's `UV_PYTHON`. Tasks don't need `turbo exec`, because `turbo run` already uses the managed tools. Use `turbo exec` for scripts, CI steps, and other commands outside the task graph. For commands you type in an interactive shell, the [shell hook](/docs/reference/hook) puts the same tools on `PATH`.

## Arguments

Everything after `--` is the command and its arguments, passed through unchanged. The `--` is required, so nothing after it is read as a `turbo` flag.

Before `--`, `turbo exec` accepts global flags such as `--cwd` and `--root-turbo-json`. It has no setup, lock, or task flags.

To run a task named `exec`, use `turbo run exec`.

## Behavior

- **Working directory.** The command runs in your current directory, which can be anywhere inside the repository. With `--cwd`, it runs in that directory instead.
- **Never installs.** `turbo exec` never installs or downloads tools and never changes `turbo.lock`. If the repository has no `turbo.lock`, or its managed tools are missing or out of date, it fails before running anything and tells you to run `turbo setup`. It never falls back to tools on your `PATH`.
- **Clone-local tools.** After [`turbo setup --no-lock`](/docs/reference/setup#--no-lock), `turbo exec` uses the tools it installed for this clone.
- **[`verify-system`](/docs/reference/setup-policy#verify-system) tools.** `turbo exec` checks them on `PATH` against `turbo.lock` and runs the command with your `PATH` unchanged.

```txt title="Terminal"
  x `turbo exec` requires managed setup, but the repository root has no
  | turbo.lock or `turbo setup --no-lock` tools
  help: Run `turbo setup` (or `turbo setup --no-lock` for this clone only)
        first. No command was run. `turbo exec` never falls back to tools on
        the host PATH.
```

## Exit codes and signals

`turbo exec` behaves as if you ran the command directly:

- It exits with the command's exit code.
- Stopping `turbo exec` stops the command.

On macOS and Linux, `turbo exec` replaces itself with the command once the environment is ready, the way a shell's `exec` does. Every signal, including `SIGKILL`, reaches the command directly, and a command that a signal stops exits with that signal, which shells report as `128` plus the signal number.

When the global `turbo` hands off to a [repository-local `turbo`](/docs/core-concepts/managed-toolchains#repository-local-turbo), the local `turbo` stays the command's parent. It forwards `SIGTERM` and `SIGHUP` to the command as `SIGTERM`, Ctrl+C in a terminal reaches the command once, and a signal death becomes exit code `128` plus the signal number. Killing that global `turbo` with `SIGKILL` can leave the command running.

On Windows, the command shares `turbo`'s console, so Ctrl+C reaches it directly. It runs in a job object: terminating `turbo exec` also terminates the command and every process it started. After the command exits on its own, processes it deliberately left running keep running. Exit codes, including `NTSTATUS` values, pass through unchanged.

## Windows

On Windows, `turbo exec` finds managed programs through `PATHEXT`, so `turbo exec -- pnpm install` runs the managed `pnpm.cmd`, and arguments reach `.exe` programs unchanged. Use `turbo exec` in `cmd.exe` and Git Bash, where the shell hook isn't available. See [Managed toolchain platforms](/docs/reference/managed-toolchain-platforms#windows).

## Supported platforms

`turbo exec` supports the same tools and platforms as managed `turbo run`. See [Managed toolchain platforms](/docs/reference/managed-toolchain-platforms).
