# Turborepo 2.11

<Date>Wednesday, August 5th, 2026</Date>

<Authors authors={["anthonyshew"]} />

Turborepo 2.11 expands what's possible in your Turborepo:

- [**Rust and Python native support (Experimental)**](#native-support-for-rust-and-python-experimental): Add Cargo and uv workspaces to your Task Graph
- [**`devEngines.packageManager` support**](#devenginespackagemanager-support): Declare your package manager with modern Node.js convention
- [**nub and aube support**](#nub-and-aube-support): New JavaScript package managers
- [**Production pruning**](#production-pruning): Exclude development-only workspace packages from `turbo prune` outputs

In addition to these new features, this is the first release of Turborepo with zero known bugs.

## Native support for Rust and Python (Experimental)

Turborepo can now discover packages and dependency relationships from Cargo and uv workspaces, putting each language toolchain into the same [Task Graph](/docs/core-concepts/package-and-task-graph#task-graph). This brings Turborepo's [task scheduling](/docs/crafting-your-repository/configuring-tasks), [filtering](/docs/crafting-your-repository/running-tasks#using-filters), [affectedness calculations](/docs/crafting-your-repository/constructing-ci#running-only-affected-tasks), [Watch Mode](/docs/crafting-your-repository/developing-applications#watch-mode), and [pruning](/docs/reference/prune) to your Rust and Python projects. You get one CLI, `turbo`, to handle all the tasks in your monorepo.

You can use any of these languages by themselves or bring JavaScript, Rust, and Python together in one unified experience. When you're using multiple languages, Turborepo will automatically parallelize your tasks to get your work done as fast as possible.

| Turborepo command                        | Task examples                                   |
| ---------------------------------------- | ----------------------------------------------- |
| `turbo run build`                        | `tsc build` + `cargo build` + `uv build`        |
| `turbo run test`                         | `vitest run` + `cargo test` + `uv run pytest`   |
| `turbo run check`                        | `tsc` + `cargo check` + `uv run mypy`           |
| `turbo run lint`                         | `eslint` + `cargo clippy` + `uv run ruff check` |
| `turbo run format`                       | `prettier` + `cargo fmt` + `uv run ruff format` |
| `turbo run build test check lint format` | All of the commands above run in parallel       |

You can also create cross-toolchain dependencies in `turbo.json`. In the example below, tests for a Python API server wait for a Rust core package to be built:

```json title="turbo.json"
{
  "futureFlags": {
    "experimentalCargoWorkspaces": true,
    "experimentalPythonWorkspaces": true
  },
  "tasks": {
    "my-dango-api#test": {
      "dependsOn": ["rust-api-core#build"]
    }
  }
}
```

Once the Rust dependency is done building, the Django server will run its Python tests.

Native Rust and Python support is [Experimental](/docs/support-policy#experimental) and subject to change. Please provide your feedback in [GitHub Discussions](https://github.com/vercel/turborepo/discussions/categories/rfc).

### Rust with Cargo

Enable Cargo workspace support with `experimentalCargoWorkspaces` in your root `turbo.json`:

```json title="turbo.json"
{
  "futureFlags": {
    "experimentalCargoWorkspaces": true
  }
}
```

Turborepo infers common tasks and maps them to Cargo commands:

| Turborepo command  | Cargo-native task |
| ------------------ | ----------------- |
| `turbo run build`  | `cargo build`     |
| `turbo run test`   | `cargo test`      |
| `turbo run check`  | `cargo check`     |
| `turbo run lint`   | `cargo clippy`    |
| `turbo run format` | `cargo fmt`       |

Cargo remains responsible for installing dependencies, resolving dependencies, compiling crates, and scheduling the Cargo-internal build graph. The Cargo workspace continues to work the way you are used to under the hood.

To learn more, [read the Rust guide](/docs/guides/tools/rust). We look forward to hearing your feedback on [the RFC for Rust support](https://github.com/vercel/turborepo/discussions/13415).

### Python with uv

Enable uv workspace support with `experimentalPythonWorkspaces` in your root `turbo.json`:

```json title="turbo.json"
{
  "futureFlags": {
    "experimentalPythonWorkspaces": true
  }
}
```

With zero configuration, Turborepo reads the tools in your `pyproject.toml` and runs them as native tasks:

| Turborepo command  | uv-native task                |
| ------------------ | ----------------------------- |
| `turbo run build`  | `uv build --package=<name>`   |
| `turbo run test`   | `uv run --frozen pytest`      |
| `turbo run check`  | `uv run --frozen mypy`        |
| `turbo run lint`   | `uv run --frozen ruff check`  |
| `turbo run format` | `uv run --frozen ruff format` |

Ruff, Black, mypy, ty, Pyright and pytest all require zero-configuration. To learn more, [read the Python guide](/docs/guides/tools/python) and let us know of your feedback on the [Python support RFC](https://github.com/vercel/turborepo/discussions/13625).

## `devEngines.packageManager` support

For JavaScript toolchains, the `devEngines.packageManager` field is the modern way to declare the package manager expected by your repository:

```json title="package.json"
{
  "devEngines": {
    "packageManager": {
      "name": "pnpm",
      "version": "12.0.0"
    }
  }
}
```

Starting with this release, Turborepo respects this field.

In a future major version of Turborepo, the top-level `packageManager` will stop being supported to align with the current and future direction of the JavaScript ecosystem. We encourage migrating your repository to `devEngines.packageManager`.

[Read the package manager documentation](/docs/crafting-your-repository/structuring-a-repository#root-packagejson) to learn more.

## nub and aube support

Turborepo now recognizes [nub](https://nub.dev) and [aube](https://aube.jdx.dev) as JavaScript package managers.

Both of these package managers focus on improving security and speed for your repo. They use your existing npm, pnpm, Yarn, or Bun lockfile, making for easy migration.

Declare nub in your root `package.json`:

<Tabs items={["nub", "aube"]}>
<Tab value="nub">

```json title="package.json"
{
  "devEngines": {
    "packageManager": {
      "name": "nub",
      "version": "0.8.3"
    }
  }
}
```

</Tab>

<Tab value="aube">

```json title="package.json"
{
  "devEngines": {
    "packageManager": {
      "name": "aube",
      "version": "2.2.9"
    }
  }
}
```

</Tab>
</Tabs>

To try nub or aube, quickly create a monorepo with `create-turbo`:

```sh title="Terminal"
# nub
nubx create-turbo -m nub

# aube
aubx create-turbo -m aube
```

## Production pruning

When preparing a deployment from a monorepo, it can be tricky to right-size your Docker images. Turborepo's `prune` command is meant to solve this problem, trimming your monorepo down to only the code that is needed for the application to deploy and run successfully.

Until today, Turborepo would include workspace packages referenced through both dependencies _and_ development dependencies while calculating the pruning dependency closure. While this is a safe default, removing development-only workspace packages from the production image can optimize further.

In this release, we're giving you control to exclude workspace packages that are only reachable through `devDependencies` with the new `--production` flag for `turbo prune`:

```bash title="Terminal"
turbo prune web --production
```

This works across all natively supported languages, including the Experimental ones introduced in this release.

[Visit the `turbo prune` documentation](/docs/reference/prune#--production) to learn more.
