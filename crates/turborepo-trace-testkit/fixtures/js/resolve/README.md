# JS resolver fixtures

Inputs for `crates/turborepo-trace-lang-js/tests/resolve.rs`. The `resolver_*` tests call the resolver with
hand-built references; the `snapshot_*` tests trace these trees end to end and snapshot the
JSON output (`crates/turborepo-trace-lang-js/tests/snapshots/resolve__*.snap`).

`node_modules/` directories here are hand-written fixture packages, committed on purpose.

| Case | Exercises |
|---|---|
| `basic/main.js` | CommonJS: relative paths, extension probing, directory `index`, JSON leaf, `imports` (`#internal/*`), package self-reference (`app/feature`), builtins (`fs`, `node:fs/promises`), `main`, `exports` with the `require` condition plus the legacy `main` (nft without `exportsOnly`), `exports` subpath patterns, `exports`-only packages, scoped packages, resolution from inside `node_modules`, unresolved package and relative path, case mismatch |
| `basic/esm.mjs` | ESM: `exports` with the `import` condition, nested `package.json` (`esm/package.json` with `type`), `module` field ignored by default, `export ... from`, `import()` |
| `ts/src/main.ts` | `.js` to `.ts` and `.mjs` to `.mts` extension aliases, tsconfig `paths`, `.tsx` probing, `import type` (excluded unless `--include-types`), declaration-only targets (`decl.d.ts`) |
| `ts/src/plain.js` | A JS file importing `./a.js` where only `a.ts` exists (falls back to the TS source); tsconfig `paths` apply although the config has no `allowJs` (bundler fallback) |
| `tsconfig-js/` | tsconfig `paths` for JS files, Next.js style: `allowJs` with an `include` naming `.js`/`.mjs` (`src/page.js`, `src/esm.mjs`), a `.jsx` file outside `include` that gets the package's config through the fallback (`src/widget.jsx`), and a JS-only app with `jsconfig.json` (`jsapp/`) |
| `tsconfig-broken/` | A root config with four project references: a missing directory, one whose `extends` names an uninstalled package, one whose `extends` file is not JSON, and a working one. The root `paths`, relative imports and the working reference keep resolving; one `parse_incomplete` record names the skipped references |
| `workspace/` | pnpm workspace (`pnpm-workspace.yaml`) traced with `--externals stop`: `apps/web` reaches `@ws/lib` (a `workspace:` link in its own `node_modules`) and `@ws/hoisted` (a link in the root `node_modules`), both first party and traversed; `dep` (real path in `node_modules/.pnpm`) and `linked` (linked to `../workspace-linked`, outside the workspace) are external |
| `pnpm/` | pnpm layout: `node_modules/foo` links to `.pnpm/foo@1.0.0/node_modules/foo`, whose dependency `bar` links to `../../bar@2.0.0/node_modules/bar`. Graph nodes are real paths, link paths are emitted as files, and nft `symlinks` maps them to their targets |
| `dynamic/` | M2 resolution (`tests/resolve_dynamic.rs`, references scripted in the shapes the extractor emits): pattern requires (`./locales/*.json`, `./plugins/*`, `./plugins/*/index` with extension probing, no match), alternatives, `__dirname` reads (literal and pattern, also from `lib/helper.js` via `../data/*.json`), `readdir` of a directory, a probe of a missing file (quiet), `path.join(__dirname, x)` (refused as too broad, as nft), cwd-relative reads against `--cwd runtime/`, `new Worker`, `fork` with extension probing, `new URL(..., import.meta.url)` assets, nested `node_modules` and README files skipped by globs, a reference-less file still getting its `package.json` |
| `special/` | Package special cases with fake package layouts for `--target linux/x64` and `darwin/arm64`: `bindings` (better-sqlite3 < 12), better-sqlite3 >= 12 prebuilds, `node-gyp-build` prebuilds per platform and libc, `@mapbox/node-pre-gyp` `binary.module_path` (fully expanded, and with `{node_abi}` as a partial pattern), `node-gyp-build-optional-packages` platform packages, `sharp` optional platform packages and libvips, `esbuild` binary package, Prisma engines per platform, `semver` preload, a directly required `.node` with package-local shared libraries, and a loader with no addon on disk |
| `nft-assets/` | nft's path-value assets (`tests/nft_gaps.rs`, real extractor): `path.join(__dirname, ...)` assigned, returned, inside a `spawn` array, a `${__dirname}` template read through an undeclared `fs`, a webpack-style namespace `ns().join(process.cwd(), ...)` (cwd, guessed `path.join`), a directory value expanded as a whole (with a record), `path.join(require.resolve('wasm-pkg'), '../engine.wasm')`, a missing path (quiet), an ancestor and the bare anchors (never emitted) |
| `nft-loaders/` | Loaders beyond literal `require` (`tests/nft_gaps.rs`): a concise-arrow require wrapper, `resolve-from` relative to `__dirname`, a top-level `var` with env-dependent alternatives, a pino transport `target`, `module.register` with `pathToFileURL(__filename)`, and a browserify bundle whose external dependency is required and whose bundled one is not |
| `nft-conditions/` | Resolver conditions (`tests/nft_gaps.rs`): `module-sync` next to `require` in `exports` and in `imports` (`#internal`), the `browser` field remapping with the `browser` condition only, node-gyp-build prebuilds in libc-tagged directories (`prebuilds/linuxglibc-x64`), and `listing/index.js` reading its own directory while it is also the cwd |
| `outside/` | `app/` traced with `--base app`: `require('shared')` resolves to `../node_modules/shared`, reported as `outside_base` |
